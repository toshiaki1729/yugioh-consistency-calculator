# 初動率計算機 計算の仕組みと開発者向けの情報

[README に戻る](../README.md) ／ [詳しい使い方](guide.md)

このページには、計算の方法を詳しく知りたい方や開発者向けの情報をまとめています。使い方は[詳しい使い方](guide.md)をご覧ください。

## 計算の方法

計算はすべてブラウザ内（Web Worker）で行います。デッキの内容に応じて、次の 3 つの方法を自動で切り替えます。

デッキに `mainFillTarget` が設定されており、実際のメインデッキの枚数が設定値より少ない場合は、その差を補って計算入力を作成します。classes 方式（厳密・サンプリング）では、補う枚数を `otherCount`（どのスロット・条件にも属さないカードの枚数）に加算します。シミュレーションでは、すべての対象を解決した後に、どのスロット・条件・効果の対象にも属さないカードを `cards` の末尾に追加します。設定がない場合や、実際の枚数が設定値以上の場合は補いません。なお、デッキが 60 枚を超えていないかの検査は実際の枚数で行い、手札枚数がデッキ枚数を超えていないかの検査は補った後の枚数で行います。

### 厳密

ドロー効果も「デッキの上から除外しても残っている」の条件もないデッキでは、多変量超幾何分布で正確な確率を求めます。

- スロットと条件への当てはまり方が同じカードを 1 つのクラスにまとめ、クラスごとの手札の枚数をすべて列挙して、組み合わせの数で重み付けします。
- 「種類違い」に関係するカードは、名前が同じでも CardId ごとに別のクラスにします。
- 複数のスロットへの割り当ては、最大流で判定します（手札の同じ 1 枚を 2 つのスロットには使いません）。
- 「デッキに残っている」の条件も、この方法のまま扱えます。

### 「種類違い」の判定

名前のキーは、読み取ったルール上の名前のうち最初の 1 つ、無ければ CardData のカード名を `normalizeForMatch`（NFKC・英字の小文字化・空白除去）で正規化した値です。CardData が無い場合は、同じ CardId を持つ最初のメインデッキのエントリに保存された名前を使います。複数のルール上の名前から最初の 1 つを選ぶのは、アプリ独自の仕様です。

種類違いのスロットは、所属クラスを名前のキーでまとめた `distinctGroups` を持ちます。すべて 1 要素のまとまりなら省略し、従来どおり各クラスを別の種類として扱います。クラスを名前だけで統合することはありません。パターン単独への射影では、旧クラス番号から新クラス番号への対応にもとづいてまとまりを作り直します。シミュレーションでは、クラス番号の代わりにカード番号を使います。

最大流の経路は、始点 → スロット（容量は必要枚数）→ そのスロット専用の名前ノード（容量 1）→ そのスロットに属する同名のクラス（容量は必要枚数の合計）→ 終点（容量は手札の枚数）です。名前ノードはスロット間で共有しません。1 要素のまとまりは容量 1 でクラスへ直接つなぎ、種類違いでないスロットも必要枚数の合計を容量としてクラスへ直接つなぎます。

スロットが 1 つの簡易判定と、最大流の前の容量確認でも、手札に 1 枚以上ある名前のまとまりを数えます。種類違いでないスロットは枚数で数えます。厳密計算・サンプリング・シミュレーションと、効果で選ぶ候補が初動を完成させるかの判定には、同じ判定器を使います。

### サンプリング

厳密計算の前に数えた状態数が **2,000,000 を超える場合**のみ、固定シードの乱数で **200,000 回**手札を引いて推定します。全体と各パターン、および手札の枚数ごとに切り替えを判断します。結果には **95% Wilson スコア区間**を付与します。

### シミュレーション（20 万回）

メインデッキのカードにドロー効果が登録されている場合、または有効なパターンに「デッキの上から除外しても残っている」がある場合に使用します。手札の枚数ごとに、固定シードの乱数でデッキの並びを **200,000 回**シャッフルして手札を引き、登録されたドロー効果を実際に使用して、初動になった回数を数えます。結果には **95% Wilson スコア区間**を付与します。この区間は試行回数による誤差の目安であり、効果の近似による差は含みません。

ドロー効果の使い方（詳細）:

- 手札が初動になっていないときだけ、一覧の上から順に、使えるドロー効果を 1 つずつ使い、初動になったと判断した時点でやめます。
- 効果は手順を最後まで処理してから判定します。使用前に、デッキの必要枚数と手札から手放すカードが足りているかを確認し、不足していればその効果は使用しません。手放すカードには、発動するカード自身を含めません。
- 効果処理でカードを選ぶ際は、その時点で判明している情報のみで決定し、これから引くカードは参照しません。選んだ直後に初動となる候補を優先します。該当する候補がない場合、手札に加える際は目標のスロットに多く関係するカードを、手放す際はスロットや条件への関係が少ないカードを選びます。優先度が同じ場合は、カード番号の小さい順とします。
- 「サーチ」の後はデッキをシャッフルします。「めくって 1 枚を手札に」の残りは、デッキの一番下に戻します。「めくって 1 枚を手札に」と「サーチ」はドローとして扱いません。
- ドロー効果の使用を止める判断（初動になったか）には、手札のスロットと「デッキに残っている」「ドロー効果で送ったカードに含まれる／含まれない」の条件を使用します。「デッキの上から除外しても残っている」は、まだ見ていないデッキの上を参照することになるため、止める判断には使わず、止まった後の最終判定にのみ使用します。
- 全体と各パターンは、それぞれ別の目標として同じデッキの並びから処理を進めます。「全体」は、いずれかのパターンが成立したと判断した時点で処理を止めるため、その後の「デッキの上から除外しても残っている」の判定で不成立となった場合、全体の確率が各パターン単独の確率を下回ることがあります。

### 結果の表示

- 計算の後にデッキ・グループ・パターンなどを変えると「古い結果（再計算してください）」を表示します。
- デッキを切り替えると、実行中の計算を中止し、別のデッキの結果は表示しません。

## 条件の判定の詳細

- 「テーマ『○○』カード」は、カード名・読み・ルール上の名前・テキストの「〜カードとしても扱う」に「○○」が含まれるかで判定する近似です。
- 「『○○』が記されたカード」は、テキスト（ペンデュラム効果を含む）に「○○」が引用されているかで判定する近似処理です。読み取ったルール上の名前を定義している文だけを丸ごと除外し、ほかの文にあるその名前の記述は残します。「○○」の直後が「モンスター」「カード」「魔法」「罠」の場合（テーマ指定）と、そのカード自身の名前は数えません。たとえば《白き竜の落胤》の定義文は除外しますが、別の文にある「「アルバスの落胤」のカード名が記されたモンスター」は判定対象です。
- 「カード名キーワード」と「テーマ『○○』カード」は、カード名・読み・ルール上の名前を `normalizeKana` で照合し、ひらがな・カタカナを区別しません。区切りの記号（「・」など）は区別します。
- ルール上の名前は、通常・ペンデュラムのテキストから、手札で有効な定義文だけを読み取ります。「このカード名はルール上」「このカードのカード名はルール上」「このカードのカード名は」に続く「「Y」として扱う。」、または「このカードのカード名は、Lに存在する限り「Y」として扱う。」で場所 L に「手札」を含む文が対象です。効果番号・「●」・前後の空白を除いた文全体で照合します。名前が増える「〜としても扱う」や、フィールド・墓地だけで有効な記述は対象外です。カスタムカードと公式ページの補助データにも同じ規則を適用します。
- グループへの所属はカードごとに固定します。手札で有効なルール上の名前を、デッキの残数・サーチ候補・ドロー効果で送ったカードの条件にも適用する近似処理です。「特定のカード」の条件とスロットは CardId で指定したカードだけを数え、同名の別カードを含めません。
- カード検索では、ひらがな・カタカナの違いと区切りの記号（「・」、ハイフン類、「＝」）を無視します。取り込みでのカード名の照合は、完全に一致するものだけです。
- 「種類違い」は名前のキーが異なることを意味し、そのスロット内だけに適用されます。別のスロットでは同名カードの別個体を使えます。カードDBの読み込みで名前のまとまりが変わると計算入力も変わり、前の結果は「古い結果」になります。
- 名前判定の追加により、既存グループの該当カードが増えたり、否定条件では減ったりする場合があります。同名カードを別の種類として数えなくなるため、種類違いのパターンの確率が下がる場合もあります。
- 攻撃力・守備力が「?」のカードや、その数値を持たないカードは、範囲の条件に当てはまりません。エクシーズモンスターはレベルの条件に当てはまりません。
- 追加の条件の上限は、1 パターンに 8 個です。ドロー効果は、デッキ全体で 30 個、1 つの効果の手順は 6 個までです。

## 保存の詳細

- 変更は 500ms 後に、同じブラウザ・同じサイトの localStorage に自動で保存します。ページを離れるときや画面が非表示になるときにも、未保存の変更を書き込みます。
- 保存の形式は v2 です。v2 のデータが無い場合は、前の版（v1）のデータを残したまま読み込み、以後は v2 に保存します。
- デッキの JSON ファイルは version 2 で書き出し、version 1 のファイルも読み込めます（追加の条件とドロー効果は空の状態から始めます）。
- デッキ取り込み用のブックマークレットは、読み込み処理だけを行う短いコードです。実行すると、アプリと同じ場所にある `bookmarklet.js`（ビルド時に `src/importer/bookmarklet.src.js` から生成）を読み込みます。Android の Chrome では、ブックマークの編集欄に貼り付けた URL が 5,000 文字で切り捨てられるため、本体はブックマークレットに埋め込まず、アプリから読み込む方式にしています。読み込むときは、リクエストにデッキの情報を含めず、Referer も送りません。読み込まれた `bookmarklet.js` が、開いているデッキページの内容を読み取ります。読み取ったデータは URL の末尾（ハッシュ）で受け渡し、アプリが読み込んだ直後に URL から消去します。アプリは原則として新しいタブで開き、ポップアップがブロックされた場合は同じタブで開きます。URL が長すぎる場合や、同じタブでも開けない場合は、JSON のコピーに切り替わります。

## 開発

Node.js 18 以上を使います。

```sh
npm install
npm run dev
npm test
npm run build
```

Vite + React 18 + TypeScript の静的 SPA です。テストには Vitest、UI のテストには happy-dom を使います。テストのカードデータは `test/fixtures/` を使い、実データには依存しません。

### カードDBの更新

```sh
npm run fetch:cards
npm run build:cards
```

yaml-yugi の `cards.json` を `data-src/cards.json` に取得し、日本語のカードDB `public/data/cards.ja.json` を生成します。`data-src/` は git の管理外です。生成された **`public/data/cards.ja.json` を更新してコミット**してください。生成されたファイルは手で編集しないでください。入出力のパスを変える場合は `npm run build:cards -- 入力パス 出力パス` で指定できます。カードDBの生成日時は、アプリのフッターに表示されます。

### 公開（静的ホスティング）

`npm run build` で作られる **`dist/` の中身を、静的ホスティングの公開ディレクトリに置くだけ**で配信できます。`base: './'` のため、サブディレクトリにも置けます。サーバ側のプログラムは不要です。ローカルで確認するときも、HTTP サーバで配信してください。ブックマークレットの本体（`bookmarklet.js`）も `dist/` に出力されます。ブックマークレットには置き場所の URL が含まれるため、置き場所の URL が変わった場合は登録し直してください。本体（`bookmarklet.js`）を更新しただけであれば、登録し直す必要はありません。

GitHub Pages への公開は、`master` への push のときに `.github/workflows/deploy.yml` で行います。フッターのソースへのリンクは、ビルド時の `VITE_SOURCE_URL` で決まります（このワークフローでは公開版のコミットの URL を設定します。未設定の場合や `https://` で始まらない値の場合は、リンクを表示しません）。
