# 初動率計算機

遊戯王 OCG のデッキと初動パターンを入力し、最初の手札で展開を始められる確率を計算する非公式の Web アプリです。先攻 5 枚・後攻 6 枚と、追加の手札枚数 1〜10 枚を計算できます。計算はブラウザ内の Web Worker で行います。

カードの検索・枚数編集、条件でまとめるカードグループ、複数スロットからなる初動パターンに対応します。エクストラ・サイドは保存できますが、確率計算の対象はメインデッキのみです。メイン 40〜60 枚以外は注意を表示し、60 枚超は計算できません。禁止・制限、ドロー・サーチ効果、対戦中の妨害は判定しません。カード画像は表示しません。

## デッキを取り込む

「デッキ」タブの「公式カードデータベースから取り込む」を開きます。

### PC

1. 「初動率計算機に取り込む」リンクをブラウザのブックマークバーへドラッグします。
2. [公式カードデータベース（遊戯王ニューロン）](https://www.db.yugioh-card.com/yugiohdb/)で取り込みたいデッキの詳細ページを開きます。自分の非公開デッキはログインした状態で開きます。
3. 登録したブックマークを実行します。アプリが開いたら枚数と未解決カードを確認し、「取り込みを確定」を押します。

### スマートフォン

1. アプリで「コードをコピー」を押します。コピーできない場合は表示されたコードを手動でコピーします。
2. 任意のページをブックマークし、ブックマークの編集画面で URL をコピーしたコードに置き換えます。先頭の `javascript:` も含めて保存します。
3. 公式DBのデッキ詳細ページを開き、そのページ上で登録したブックマークを実行します。アドレスバーにブックマーク名を入力して候補を選ぶ方法もあります。操作はブラウザによって異なります。
4. アプリに表示された内容を確認して取り込みを確定します。実機スマートフォンでの動作は保証していません。

ブックマークレットは開いている公式ページの DOM を読みます。アプリは URL ハッシュを読み取った直後に消します。ポップアップが開けない場合や URL が長すぎる場合は JSON コピーに切り替わるので、アプリの貼り付け欄に貼り付けてください。自動コピーも失敗した場合は、公式ページに出る枠内の JSON を手動でコピーします。

貼り付け欄にはブックマークレットの JSON または次のようなテキストを入力できます。

```text
【メイン】
3 灰流うらら
青眼の白龍 x3
【エクストラ】
1 Ｎｏ．３９ 希望皇ホープ
```

未解決カードは候補・カード検索から選ぶか、カスタムカードとして属性を入力するか、「取り込まない」を選びます。取り込み先は新しいデッキまたは現在のデッキの置き換えです。カード検索からの追加、枚数の増減、区分の移動もできます。

## グループと初動パターン

「カードグループ」タブでグループを作成し、名前と条件を設定します。条件は AND / OR、否定、1 段のまとまりで組み合わせます。該当カード一覧を確認し、条件外のカードを手動追加したり、該当カードを除外したりできます。除外は手動追加より優先します。

「初動パターン」タブでパターンを作り、「スロットを追加」で対象と必要枚数を指定します。「対象」の「グループ: …」または「カード: …」から選択します。グループを作らず特定カードだけでパターンを作ることもできます。パターン内の全スロットを満たすと成立し、有効なパターンのうち 1 つでも成立すれば全体の初動成功です。同じ 1 枚を別スロットに重複して使うことはできません。

### 例 1: 「X」モンスター 1 枚 + 任意の魔法罠 1 枚

1. グループ「Xモンスター」を作成し、最上位を「すべて満たす」にします。「テーマ『X』カード」のキーワードに実際のテーマ名（例: ブルーアイズ）を入力し、「カードの種類」でモンスターを選びます。
2. グループ「魔法罠」を作成し、「カードの種類」で魔法と罠を選びます。この複数選択はいずれかに一致する条件です。
3. パターンを作成し、スロットを 2 つ追加します。「グループ: Xモンスター」を 1 枚、「グループ: 魔法罠」を 1 枚に設定します。

### 例 2: レベル 4 以下・攻撃力 1500 以下のモンスター 2 種

1. グループを作成し、「すべて満たす」で「カードの種類 = モンスター」「レベルの以下 = 4」「攻撃力の以下 = 1500」の 3 条件を設定します。「以上」は空欄で構いません。
2. パターンにそのグループのスロットを 1 つ追加し、必要枚数を 2 にして「種類違い」をチェックします。

### 条件の注意点

- テーマ条件はカード名・読み・「〜カードとしても扱う」のテキストからの近似です。公式ルール上のテーマ判定と一致しない場合は手動追加・除外で補正してください。
- 「X」が記されたカードも近似です。引用されたカード名を探し、「X」モンスター・カード・魔法・罠のようなテーマ指定と、そのカード自身の名前の記述を除きます。ペンデュラム効果も対象です。
- 「種類違い」は別の CardId（カードDB上の別カード）です。ルール上の「同名カード扱い」は再現しません。種類違いはそのスロットの中だけに適用され、別スロット同士では同じ CardId の別の 1 枚を使えます。
- 攻守の `?` や存在しない数値は範囲条件に一致しません。エクシーズはレベル条件に一致しません。
- 未取得カードには条件式を評価しません。グループへの手動追加か、パターンの特定カード指定を使ってください。

## 計算結果

「計算する」を押すと先攻・後攻の初動率と、先攻 5 枚でのパターン別確率、方式、計算時間を表示します。追加の手札枚数も指定できます。手札枚数がメインデッキ枚数を超える場合は計算できません。計算中は進捗を表示し、「中止」で止められます。狭い画面では下部の結果バーを押すと結果全体が展開します。

原則は多変量超幾何分布の厳密計算です。スロットへの所属が同じカードをまとめたクラスごとに手札の枚数を列挙し、組み合わせ数で重み付けします。「種類違い」に関係するカードは CardId ごとに分けます。複数スロットへの割り当ては最大流で判定します。

列挙前に数えた状態数が **2,000,000 を超える場合**だけ、固定シードの乱数による **200,000 回**のサンプリングに切り替わります。方式は手札枚数ごと、全体・各パターンごとに判定します。サンプリングには **95% Wilson スコア区間**を併記します。成功が 0 回・全成功でも区間の幅は 0 になりません。全体と単独の推定は別々なので、サンプリング誤差で全体が単独を下回る場合があります。

入力が変わった結果には「古い結果（再計算してください）」を表示します。デッキ切り替え時は実行中の計算を中止し、別デッキの結果は表示しません。

## 保存と復旧

変更は 500ms 後に同じブラウザ・同じサイトの localStorage に自動保存し、ページを離れるときや非表示になるときも未保存分を書き込みます。ヘッダーの保存状態を確認してください。クラウド同期はありません。ブラウザの保存領域の消去や保存失敗に備え、「JSON 書き出し」でデッキを保存できます。「JSON 読み込み」はカード・グループ・パターンを新しいデッキとして追加します。

想定外の画面エラー時には「問題が発生しました」と保存状態を表示します。必要なら「現在のデッキを JSON で書き出す」で退避してから再読み込みしてください。画面エラーによって localStorage を削除することはありません。

## 開発

Node.js 18 以上を使用します。

```sh
npm install
npm run dev
npm test
npm run build
```

Vite + React 18 + TypeScript の静的 SPA です。テストは Vitest、UI テストは happy-dom を使います。テストのカードデータは `test/fixtures/` を使い、実データに依存しません。

### カードDBの更新

```sh
npm run fetch:cards
npm run build:cards
```

yaml-yugi の `cards.json` を `data-src/cards.json` に取得し、日本語カードDB `public/data/cards.ja.json` を生成します。`data-src/` は git 管理外です。生成された **`public/data/cards.ja.json` を更新してコミット**してください。生成物は手で編集しません。変換時に変換・除外・警告の件数を表示します。入力・出力の変更は `npm run build:cards -- 入力パス 出力パス` で指定できます。DB生成日時はアプリのフッターにローカル時刻で表示されます。

### 静的ホスティング

`npm run build` でできる **`dist/` の内容を静的ホスティングの公開ディレクトリに置くだけ**で配信できます。`base: './'` のためサブディレクトリにも配置できます。サーバ側プログラムは不要です。ローカル確認も HTTP サーバで配信してください。配置先の URL が変わった場合はブックマークレットを登録し直してください。
