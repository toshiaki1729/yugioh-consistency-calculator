# 初動率計算機

遊戯王 OCG のデッキと初動パターンを入力し、最初のターンに展開を始められる確率（初動率）を計算する非公式の Web アプリです。先攻 5 枚・後攻 6 枚のほか、追加の手札枚数（1〜10 枚）でも計算できます。計算はブラウザ内の Web Worker で行います。

[公開ページ](https://toshiaki1729.github.io/yugioh-consistency-calculator/)から利用できます。ソースコードは [GitHub リポジトリ](https://github.com/toshiaki1729/yugioh-consistency-calculator)で公開しています。

カードの検索や枚数の編集、条件でカードをまとめるカードグループ、複数のスロットを組み合わせる初動パターンに対応しています。ドロー・サーチなどの効果や、初動パターンの追加の条件も自分で設定できます。エクストラ・サイドも保存できますが、確率計算の対象はメインデッキのみです。メインデッキが 40〜60 枚でない場合は注意を表示し、60 枚を超える場合は計算できません。禁止・制限、対戦中の妨害は判定しません。カード画像は表示しません。

## デッキを取り込む

「デッキ」タブの「公式カードデータベースから取り込む」を開きます。

ブックマークレットは、このアプリの[公開ページ](https://toshiaki1729.github.io/yugioh-consistency-calculator/)で生成したものだけを使ってください。ほかのサイトで配られたブックマークレットは、デッキの内容（非公開デッキを含む）を別のサイトに送る可能性があります。

### PC

1. 「初動率計算機に取り込む」リンクをブラウザのブックマークバーへドラッグします。
2. [公式カードデータベース（遊戯王ニューロン）](https://www.db.yugioh-card.com/yugiohdb/)で取り込みたいデッキの詳細ページを開きます。自分の非公開デッキはログインした状態で開きます。
3. 登録したブックマークを実行します。アプリが開いたら枚数と未解決カードを確認し、「取り込みを確定」を押します。

### スマートフォン

1. アプリで「コードをコピー」を押します。コピーできない場合は表示されたコードを手動でコピーします。
2. 任意のページをブックマークし、ブックマークの編集画面で URL をコピーしたコードに置き換えます。先頭の `javascript:` も含めて保存します。
3. 公式カードデータベースのデッキ詳細ページを開き、そのページ上で登録したブックマークを実行します。アドレスバーにブックマーク名を入力して候補を選ぶ方法もあります。操作はブラウザによって異なります。
4. アプリが開いたら内容を確認し、「取り込みを確定」を押します。スマートフォンの実機での動作は保証していません。

ブックマークレットは、開いているデッキ詳細ページの内容を読み取ります。取り込み用のデータは URL の末尾（ハッシュ）で渡され、アプリが読み取った直後に消去されます。ポップアップを開けない場合や URL が長すぎる場合は JSON のコピーに切り替わるため、アプリの取り込み欄に貼り付けてください。自動コピーにも失敗した場合は、デッキ詳細ページに表示される枠内の JSON を手動でコピーしてください。

取り込み欄には、ブックマークレットの JSON または次のようなテキストを入力できます。

```text
【メイン】
3 灰流うらら
青眼の白龍 x3
【エクストラ】
1 Ｎｏ．３９ 希望皇ホープ
```

未解決カードは、候補やカード検索から選ぶか、カスタムカードとしてカード情報を入力するか、「取り込まない」を選びます。取り込み先は、新しいデッキの作成か現在のデッキの置き換えを選べます。取り込み後も、カード検索からの追加、枚数の増減、区分の移動ができます。

## グループと初動パターン

「カードグループ」タブでグループを作成し、名前と条件を設定します。条件は AND / OR、否定、1 段までのまとまりで組み合わせられます。該当カードの一覧を確認しながら、条件外のカードを手動で追加したり、該当するカードを除外したりできます。除外は手動追加より優先されます。

「初動パターン」タブでパターンを作り、「スロットを追加」で対象と必要枚数を指定します。「対象」の「グループ: …」または「カード: …」から選択します。グループを作らずに特定のカードだけでパターンを作ることもできます。パターン内のすべてのスロットと、設定した追加の条件を満たすと成立します。有効なパターンのうち 1 つでも成立すれば全体の初動成功です。手札の同じ 1 枚を別のスロットで重複して使うことはできません。

### 例 1: 「X」モンスター 1 枚 + 任意の魔法罠 1 枚

1. グループ「Xモンスター」を作成し、最上位を「すべて満たす」にします。「テーマ『X』カード」のキーワードに実際のテーマ名（例: ブルーアイズ）を入力し、「カードの種類」でモンスターを選びます。
2. グループ「魔法罠」を作成し、「カードの種類」で魔法と罠を選びます。この複数選択は、いずれかに一致する条件になります。
3. パターンを作成し、スロットを 2 つ追加します。「グループ: Xモンスター」を 1 枚、「グループ: 魔法罠」を 1 枚に設定します。

### 例 2: レベル 4 以下・攻撃力 1500 以下のモンスター 2 種

1. グループを作成し、「すべて満たす」で「カードの種類 = モンスター」「レベルの以下 = 4」「攻撃力の以下 = 1500」の 3 条件を設定します。「以上」は空欄で構いません。
2. パターンにそのグループのスロットを 1 つ追加し、必要枚数を 2 にして「種類違い」にチェックを入れます。

### 条件の注意点

- テーマの条件は、カード名・読み・「〜カードとしても扱う」のテキストをもとにした近似です。公式ルール上のテーマ判定と一致しない場合は、手動で追加・除外して調整してください。
- 「X」が記されたカードの条件も近似です。テキスト内で引用されたカード名を探し、「X」モンスター・カード・魔法・罠のようなテーマ指定と、そのカード自身の名前を除いて判定します。ペンデュラム効果も対象に含められます。
- 「種類違い」は、CardId（カードDB上の別カード）が異なることを意味します。ルール上の「同名カード扱い」は再現しません。「種類違い」はそのスロット内だけに適用されるため、別のスロット同士では同じ CardId の別の 1 枚を使えます。
- 攻撃力・守備力の `?` や存在しない数値は、範囲条件に一致しません。エクシーズはレベルの条件に一致しません。
- 未取得カードは条件で判定できません。グループに手動で追加するか、パターンで特定のカードとして指定してください。

## ドロー効果と追加の条件

「初動パターン」タブでは、手札の組み合わせに「追加の条件」を付けられます。「ドロー効果」タブでは、手札から使う効果をカードごとに定義できます。計算できるのは、最初のターンにドロー効果で手札を増やす部分の近似です。カードの効果全体や、展開がルール上可能かどうかを判定するものではありません。

### 追加の条件

パターン編集の「追加の条件」で「条件を追加」を押し、種類と対象を選びます。対象はスロットと同じ「グループ: …」「カード: …」です。条件は 1 パターンに 8 個まで設定でき、すべて満たす必要があります。スロットが無く、条件だけのパターンも作れます。

| 種類 | 判定する内容 |
|---|---|
| デッキに残っている | 判定の時点で、対象がデッキに「N 枚以上」残っていることを確認します（1〜60 枚）。素引きすると使えないカードなどに使います。 |
| ドロー効果で送ったカードに含まれない | 指定した送り先へドロー効果の手順で送ったカードに、対象が含まれないことを確認します。 |
| ドロー効果で送ったカードに含まれる | 指定した送り先へドロー効果の手順で送ったカードに、対象が 1 枚以上含まれることを確認します。 |
| デッキの上から除外しても残っている | 「上から X 枚を除外」（1〜20 枚）した後も、対象が「N 枚以上」（1〜60 枚）残るかを確認します。判定だけを行い、デッキのカードは実際には移動しません。 |

「ドロー効果で送ったカード」の送り先は、「墓地」「表側で除外」「裏側で除外」から 1 つ以上選びます。使った効果のカード自身は手札から墓地へ送りますが、この条件の対象には含めません。ドロー効果がない場合、「含まれない」は常に満たし、「含まれる」は満たしません。

### ドロー効果の設定と手順

「ドロー効果」タブで「効果を追加」を押し、メインデッキのカードを選びます。カード 1 種類につき 1 つ、デッキ全体で 30 個まで設定できます。一覧の「↑」「↓」で使う優先順を変えられます。メインデッキにないカードの効果は計算に使われません。

| 設定 | 意味 |
|---|---|
| 1 ターンに 1 回 | 同じカードの効果を 1 回だけ使います。チェックを外すと、途中で引いたものも含め、手札にある枚数だけ使えます。 |
| 最初の効果としてだけ使える | まだどのドロー効果も使っていないときだけ使えます。 |
| ドローの制限：なし | この効果によるドローの制限を付けません。 |
| ドローの制限：使った後はドローできない | この効果の処理後は、「ドロー」を含む効果を使えません。 |
| ドローの制限：効果でドローした後は使えず、使った後もドローできない | このターンに効果でドローしていたら使えず、処理後も「ドロー」を含む効果を使えません。 |

「手順を追加」で、次の手順を 1〜6 個、処理する順に並べます。「めくって 1 枚を手札に」「サーチ」はドローとして扱いません。

| 手順 | 処理 |
|---|---|
| ドロー | デッキの上から 1〜5 枚を手札に加えます。 |
| デッキの上から除外 | デッキの上から 1〜20 枚を裏側で除外します。 |
| めくって 1 枚を手札に | デッキの上から 1〜10 枚をめくり、対象に一致するカードを 1 枚手札に加え、残りをデッキの一番下へ戻します。対象を「何でも」にすることもできます。一致しなければすべて下へ戻します。 |
| サーチ | デッキの対象を 1 枚手札に加え、残りのデッキ全体をシャッフルします。対象がなければ何もしません。 |
| 手札から 1 枚を手放す | 手札の対象を 1 枚、「墓地」または「表側で除外」へ送ります。 |

「1 枚ドロー」「上から除外して 2 枚ドロー」「めくって 1 枚を手札に」「2 枚ドローして手札から 1 枚除外」「サーチして 1 枚ドロー」のひな形も使えます。確認して適用すると、選択中のカードの設定と手順をまとめて置き換えます。枚数・対象・制限は、使いたい効果に合わせて調整してください。対象が未設定の手順がある場合、対象を選ぶまで設定と手順の変更は保存されません。

### 計算での使い方の方針

手札が初動になっていないときだけ、一覧の上から順に使えるドロー効果を 1 つずつ使い、初動になったと判断した時点でやめます。効果は手順を最後まで処理してから判定します。発動前にデッキの必要枚数と手札から手放す対象があるかを確認し、足りなければその効果は使いません。手放す対象には、使う効果のカード自身を数えません。

効果で選ぶカードは、その時点の手札など分かっている情報だけで決め、この後に引くカードは見ません。選んだ直後に初動になる候補を優先します。候補がなければ、手札に加えるときは目標のスロットに多く関係するカードを、手放すときはスロット・条件に関係する数が少ないカードを選びます。同点の場合はカード番号の小さい順です。

止める判断には、手札のスロットと「デッキに残っている」「ドロー効果で送ったカードに含まれない」「ドロー効果で送ったカードに含まれる」を使います。「デッキの上から除外しても残っている」はまだ見ていないデッキの上を見ることになるため、止める判断には使わず、止まった後の最終判定にだけ使います。

### 効果と条件の例

次の例は自分で設定するためのものです。カード名から自動では登録されません。表で指定していない設定は、「最初の効果としてだけ使える」のチェックを外し、ドローの制限を「なし」にします。

| カード | 設定と手順 | この例で扱わない部分・注意点 |
|---|---|---|
| 成金ゴブリン | 「1 ターンに 1 回」を外し、「ドロー」1 枚。 | 相手の LP 回復は扱いません。 |
| 強欲で貪欲な壺 | 「1 ターンに 1 回」を入れ、「デッキの上から除外」10 枚 →「ドロー」2 枚。 | 除外されたカードの影響は、設定したパターン・条件の範囲で判定します。 |
| 強欲で金満な壺 | 「1 ターンに 1 回」「最初の効果としてだけ使える」を入れ、ドローの制限を「使った後はドローできない」にし、「ドロー」2 枚。 | EX デッキの中身とコストは扱いません。 |
| 金満で謙虚な壺 | 「1 ターンに 1 回」を入れ、ドローの制限を「効果でドローした後は使えず、使った後もドローできない」にし、「めくって 1 枚を手札に」6 枚、対象は初動に使うカードのグループ。 | ドローではありません。EX デッキの中身とコスト、相手が受けるダメージの制限は扱いません。 |
| 闇の誘惑 | 「1 ターンに 1 回」を外し、「ドロー」2 枚 →「手札から 1 枚を手放す」、対象は闇属性モンスターのグループ、送り先は「表側で除外」。 | 発動前の手札に対象があるときだけ使います。闇属性を引けることに賭けて発動し、手札を失う処理は扱いません。 |
| 天底の使徒＋共命の翼ガルーラ | 天底の使徒に「1 ターンに 1 回」を入れ、「サーチ」、対象はサーチ先のグループ →「ドロー」1 枚。 | EX デッキから墓地へ送る処理や特殊召喚の制限は扱いません。サーチ先の攻撃力などの条件は、対象のグループに自分で設定します。 |

追加の条件は、例えば次のように設定します。展開や特殊召喚の制限などは再現せず、指定した条件だけを判定します。

- 獄神影モンスター：その初動パターンに「デッキの上から除外しても残っている」を追加し、「上から X 枚を除外」を 3、対象をキーカード、「N 枚以上」を 1 にします。
- V・HERO インクリース：ファリスを経由するパターンに「デッキに残っている」を追加し、対象をインクリース、「N 枚以上」を 1 にします。
- 闇の誘惑でドーマウスを除外：スロットの無いパターンに「ドロー効果で送ったカードに含まれる」を追加し、送り先を「表側で除外」、対象をドーマウスにします。闇の誘惑のドロー効果も設定します。

### 扱わないもの

カード名からの効果の自動判定、EX デッキの中身とコスト、ドロー効果を使う順番の全探索は行いません。「強欲で謙虚な壺」のように初動の判定に使わないカードや、デッキ全体で不確定なドローを前提にする構築は対象外です。指定した手順・条件以外の処理（特殊召喚の制限、チェーン、相手の妨害など）も扱いません。

## 計算結果

「計算する」を押すと、先攻・後攻の初動率、先攻 5 枚でのパターン別の確率、計算方式、計算時間を表示します。追加の手札枚数も指定できます。手札枚数がメインデッキの枚数を超える場合は計算できません。計算中は進捗を表示し、「中止」で止められます。狭い画面では、下部の結果バーを押すと結果全体が開きます。

メインデッキにあるカードにドロー効果が設定されている場合、または有効なパターンに「デッキの上から除外しても残っている」がある場合は、「シミュレーション（20 万回）」で計算します。手札枚数ごとに、固定シードの乱数でデッキの並びを **200,000 回**シャッフルし、手札を引いて設定したドロー効果を使い、成立した回数を数えます。結果には **95% Wilson スコア区間**を付けます。この区間は試行による誤差の目安であり、効果を近似していることによる差は含みません。

シミュレーションでは、全体と各パターンを別々の目標として進めます。全体は、分かっている情報でいずれかのパターンが成立した時点で止まります。その後「デッキの上から除外しても残っている」で不成立になると、別のパターンだけを目指して効果を使い続けた場合より成功が少なくなり、全体の値が単独パターンの値を下回ることがあります。

それ以外は、原則として多変量超幾何分布による「厳密」で計算します。「デッキに残っている」の条件も厳密計算のまま扱えます。スロットと条件への当てはまり方が同じカードを 1 つのクラスにまとめ、クラスごとの手札枚数を列挙して組み合わせ数で重み付けします。「種類違い」に関係するカードは CardId ごとに分けます。複数のスロットへの割り当ては最大流で判定します。

厳密計算の列挙前に数えた状態数が **2,000,000 を超える場合**だけ、固定シードの乱数による **200,000 回**の「サンプリング」に切り替わります。厳密計算とサンプリングの選択は手札枚数ごと、および全体・各パターンごとに行います。サンプリングの結果にも **95% Wilson スコア区間**を併記します。成功が 0 回または全試行で成功した場合でも、区間の幅は 0 になりません。全体と各パターンは別々に推定するため、サンプリングの誤差によって全体の値が単独パターンの値を下回ることがあります。

計算後にデッキ・グループ・パターンなどを変更すると、「古い結果（再計算してください）」を表示します。デッキを切り替えた場合は実行中の計算を中止し、別のデッキの結果は表示しません。

## 保存と復旧

取り込みや計算のデータはブラウザの中だけで扱い、アプリが外部に送ることはありません。ただし、公開先の GitHub Pages はアクセスの記録（IP アドレスなど）を取ります。

変更内容は、500ms 後に同じブラウザ・同じサイトの localStorage に自動保存されます。ページを離れるときや画面が非表示になるときにも、未保存の変更を書き込みます。保存状態はヘッダーで確認してください。クラウド同期はありません。ブラウザの保存領域の消去や保存の失敗に備え、「JSON 書き出し」でデッキを保存できます。「JSON 読み込み」を使うと、カード・グループ・パターン・追加の条件・ドロー効果を新しいデッキとして追加できます。

ブラウザの保存先は新しい形式（v2）に変わります。v2 のデータがない場合は前の版（v1）のデータを残したまま読み込み、以後は v2 に保存します。デッキの JSON ファイルは version 2 で書き出し、前の version 1 のファイルも読み込めます（追加の条件とドロー効果は空の状態から始めます）。

Safari などでは、サイトをしばらく操作しないとブラウザの保存データが自動で消えることがあります。プライベートブラウズの終了やブラウザのデータ消去でも消えます。大事なデッキは「JSON 書き出し」でファイルに保存しておいてください。

複数のタブで開いて片方で保存が進むと、もう片方のタブは自動保存を止め、ヘッダーに「別のタブで更新されました」と表示します。そのタブの変更を残したい場合は、「JSON 書き出し」で保存してから「再読み込み」を押してください。

画面の表示中に想定外のエラーが起きた場合は、「問題が発生しました」と保存状態を表示します。必要に応じて「現在のデッキを JSON で書き出す」で保存してから再読み込みしてください。画面エラーによって localStorage のデータが削除されることはありません。

## 開発

Node.js 18 以上を使用します。

```sh
npm install
npm run dev
npm test
npm run build
```

Vite + React 18 + TypeScript の静的 SPA です。テストには Vitest、UI テストには happy-dom を使います。テストのカードデータは `test/fixtures/` を使い、実データには依存しません。

### カードDBの更新

```sh
npm run fetch:cards
npm run build:cards
```

yaml-yugi の `cards.json` を `data-src/cards.json` に取得し、日本語カードDB `public/data/cards.ja.json` を生成します。`data-src/` は git 管理外です。生成された **`public/data/cards.ja.json` を更新してコミット**してください。生成されたファイルは手で編集しないでください。変換時には変換・除外・警告の件数を表示します。入出力パスを変更する場合は `npm run build:cards -- 入力パス 出力パス` で指定できます。カードDBの生成日時は、アプリのフッターにローカル時刻で表示されます。

### 静的ホスティング

`npm run build` で生成される **`dist/` の内容を静的ホスティングの公開ディレクトリに置くだけ**で配信できます。`base: './'` のためサブディレクトリにも配置できます。サーバ側のプログラムは不要です。ローカルでの動作確認も HTTP サーバで配信してください。配置先の URL が変わった場合は、ブックマークレットを登録し直してください。

GitHub Pages へのデプロイは、`master` への push 時に `.github/workflows/deploy.yml` で行います。フッターのソースへのリンクはビルド時の `VITE_SOURCE_URL` で決まり、このワークフローでは公開版のコミットの URL を設定します。未設定の場合や `https://` で始まらない値の場合は、リンクを表示しません。
